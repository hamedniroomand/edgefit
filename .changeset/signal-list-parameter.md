The code of a signal handler is now guarded on Workers and Vercel Edge when the event is a signal that no code can change, and not only a string in quotes. The event can be a `const` string, a template literal of `const` strings, the loop variable of an array that the code writes in place (its callback must not be able to change the array), or the loop variable of the list that a class method gets from its one call. An example is `register(signals) { signals.forEach(signal => process.on(signal, stop)); }` with the call `this.register(['SIGINT', 'SIGTERM'])`. Every string must start with `SIG`. Before, `edgefit package @apollo/server` reported `node:process.kill` as an error on Workers for such a handler. A list that has a name stays a finding, because other code can change it. A method with a second call, another mention of its name in the file or in another file that edgefit reads, a list that has `'exit'`, or a body that changes or passes on the list keeps its findings. A call from a file that edgefit does not read, and a call through a computed key such as `object[name](…)`, are not seen. Such a call can hide the findings of the handler when it passes an event that is not a signal. The list of a method also gives the keys of a computed read, such as `fs[name]` in a loop over the parameter. So a `node:fs[<expression>]` warning can become the error for the exact API.
